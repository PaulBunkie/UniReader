# Исправление ошибки "Text too long" путем разбиения главы на части

Логи подтвердили, что сервер имеет лимит в 50 000 символов на запрос, а проблемная глава содержит 51 154 символа. Для решения проблемы необходимо реализовать автоматическое разбиение текста главы на фрагменты (chunks), их независимый перевод и последующую склейку.

## Анализ
1.  **Лимит**: 50 000 символов. Для безопасности будем использовать чанк в 40 000 символов.
2.  **Формат**: Текст является HTML. Нельзя разбивать посреди тега (например, `<p...|.../p>`).
3.  **Состояние**: `glossary` может обновляться после каждого перевода. Нужно передавать обновленный глоссарий в следующий чанк.

## Предлагаемые изменения

### 1. Реализация логики разбиения в `TranslationService`
Вместо одного запроса к `/translate`, метод `translateChapter` будет:
- Проверять длину `text`.
- Если она больше порога, разбивать текст на части по границам тегов (например, по закрывающим тегам `</p>`, `</div>`, `</h1>` и т.д.).
- Отправлять каждую часть отдельным запросом.
- Дожидаться завершения каждой задачи через `pollTask`.
- Склеивать результаты.
