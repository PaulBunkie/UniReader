# Расширенное логирование для отладки ошибки 400

Для решения проблемы с ошибкой 400 при переводе главы, в проект были добавлены средства расширенной диагностики. Теперь при возникновении ошибки в логах и интерфейсе будет отображаться детальная информация от сервера.

## Изменения

### [TranslationService.kt](file:///C:/Users/Владелец/AndroidStudioProjects/UniReader/app/src/main/java/com/reaido/unireader/TranslationService.kt)

1.  **Логирование размера запроса**:
    - Теперь перед отправкой главы логируется количество символов и размер тела запроса в байтах. Это поможет определить, не превышает ли глава лимиты сервера.
    ```kotlin
    Log.d("TranslationService", "Sending request to /translate (size: ${bodyString.length} chars, ${bodyString.toByteArray().size} bytes)...")
    ```

2.  **Чтение тела ошибки**:
    - Ранее при ошибке (например, 400) логировался только код. Теперь считывается тело ответа (`responseBody`), которое часто содержит JSON с описанием ошибки.
    - Сообщение об ошибке от сервера (поле `error`) теперь включается в текст исключения и будет отображаться в UI.

3.  **Улучшение логирования в TOC и опросе статуса (polling)**:
    - Аналогичные улучшения добавлены для перевода оглавления и процесса ожидания результата.

## Инструкция по проверке

1.  Запустите приложение и откройте проблемную главу.
2.  Попробуйте запустить перевод.
3.  Когда возникнет ошибка, проверьте:
    - **Logcat**: фильтр по тегу `TranslationService`. Там будет выведено тело ответа сервера.
    - **API Log (в приложении)**: Меню -> "API Log". Там также должна появиться запись `ERR ch X: 400 -> { ... }`.
4.  Пришлите текст ошибки, который появится в логах. Это позволит нам понять, нужно ли разбивать главу на части или проблема в чем-то другом.

> [!IMPORTANT]
> Если в логе будет написано `Payload Too Large`, значит сервер не принимает такие большие главы. В этом случае следующим шагом мы реализуем автоматическое разбиение текста на фрагменты.
